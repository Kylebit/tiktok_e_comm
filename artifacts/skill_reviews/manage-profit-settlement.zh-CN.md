# 利润结算 Skill（中文审阅镜像）

> 英文 [`SKILL.md`](../../domains/data_operations/skills/manage-profit-settlement/SKILL.md) 是唯一执行版本；本文件只供人工阅读，每轮随英文版更新。

TikTok、Shopee、Ozon 三条链路必须相互独立，不能用一个平台的数据补另一个平台。三者只共享带版本的商品成本快照和同一次运行的不可变汇率快照。

## 第一阶段：官方结算证据

1. 输入平台、站点、开始日和结束日；日期首尾都包含，并确认周期在站点报表时区内已经结束。
2. 读取对应平台规则和利润报表合同。
3. 运行 `scripts/pull_settlement_evidence.py`。只读取官方已结算/已放款记录；排除待处理、处理中、取消、仅送达但未结算和状态不明记录。Shopee 各站必须独立使用当地报表时区：MY `Asia/Kuala_Lumpur`（UTC+08:00）、PH `Asia/Manila`（UTC+08:00）、TH `Asia/Bangkok`（UTC+07:00）、VN `Asia/Ho_Chi_Minh`（UTC+07:00），禁止混用时区或合并站点证据。
4. 保存脱敏的 `settlement-evidence/v1` JSON/HTML，并核对时区、行数、费用组件、详情失败、checksum 和 `external_writes_performed=[]`。
5. 凭证刷新默认禁止。TikTok 得到明确批准后也只能刷新一次性副本，不能覆盖正式凭证文件；Shopee 得到明确批准并传入 `--allow-credential-refresh` 后，可以更新已配置的 token 文件，以安全保留平台可能轮换的新 refresh token，并必须在证据回执中记录刷新事实和范围。

## 第二阶段：订单级利润

1. 从只读 `shop.db` 生成以规范 seller SKU 为键的成本快照；运行时实时读取一次最新汇率并冻结为整次运行的 FX 快照，同时保留汇率提供方、提供方截至时间、快照身份和完整精度的本币兑 CNY 汇率。所有实时汇率源失败时必须停止，禁止回退配置默认值。临时成本政策为：缺少正数成本时单件按 CNY 5，成本冲突时取最高正数；两者都必须在受影响 SKU/订单上显示假设警告，不能冒充成本库事实。
2. 运行 `scripts/build_weekly_from_evidence.py`，只消费已审核的 `settlement-evidence/v1`。构建单个独立站点时必须同时传入 `--platform PLATFORM --site SITE`，禁止把不同 Shopee 站点合并进同一报表。统一在 Skill 根目录的 `report-policy.json` 修改三平台周度广告占比和 Shopee 本土履约费；默认三平台均为 22%，Shopee 本土发货每个父订单只扣一项合并后的运费仓储费 CNY 4。可用 `--policy-config` 指向其他版本化策略文件，也可用 `--ad-rate`、三个平台广告参数或 `--shopee-local-fulfillment-fee-cny` 临时覆盖本次运行。程序记录策略校验和与最终值，只写明确指定的报表目录，不写数据库、不改平台订单。
3. TikTok/Shopee 周报广告费默认按 22% 估算，不含买家运费。Shopee 必须使用官方 `order_discounted_price`（卖家折扣后的商品成交额、平台券抵扣前）作为广告基数，并把“商品折后成交额”和“买家现金实付商品金额（buyer_total_amount 减买家运费）”分列展示；平台券减少买家现金但不减少卖家商品成交额，因此禁止用现金实付作为 Shopee 广告 GMV。报表必须标记广告为估算。TikTok 结算中已有的真实广告调整先单独剔出并对账，避免再按 22% 重复扣除。
4. TikTok/Shopee 月报必须使用真实广告消耗；优先订单归因，否则按买家实付 GMV 对真实总额进行可审计分摊，不能回退为 0 或 22%。
5. Ozon V1 周报和月报的广告费默认按商品销售基数的 22% 估算，允许人工明确覆盖，政策版本为 `operator-adjustable-ad-rate/v1`，不得表述为真实广告消耗。若财务记录只有平台 SKU 且没有数量，可只读调用商品信息和 FBS 发货单接口补 seller SKU 与实际履约数量；绝不能假定数量为 1。
6. 每个平台、每个站点独立生成 JSON/HTML。TikTok 和 Shopee 必须按已结算订单 ID 额外读取官方订单详情，只把明确的 `create_time` 保存为下单时间，并与结算/放款时间分列；缺下单时间时报告质量问题，禁止用支付、发货、完成、放款或结算时间冒充。Ozon 当前若只提供处理中或发货时间，必须留空而不能伪造下单时间。Shopee 发货方式必须按站点使用官方税费证据判断：MY 的 `sales_tax_on_lvg`（低价值商品销售税 10%）存在且非 0 即为跨境，存在且为 0 即为本土；VN 的 `vat_on_imported_goods`（增值税）存在且非 0 即为跨境，存在且为 0 即为本土；PH 全部订单均为跨境；TH 只有进口增值税和进口关税两项都实际非 0 才是跨境，两项字段都存在但任一项为 0 时归为本土。各站所需字段缺失必须阻断。每个本土父订单只扣一次合并后的本土履约费，多商品行按成交额稳定分摊，并把金额、参数版本和税费证据留在 JSON。同一报告周期内，同一订单商品行的多次结算事实只有在商品身份、数量一致，且最多一个事实具有正数广告基数时才能合并；否则阻断。合并时净结算与费用相加，商品成本和估算广告只扣一次，并在 JSON/HTML 保留全部源事实身份与时间。订单行初始按结算时间降序排列；结算时间相同则按订单 ID、订单行 ID 升序稳定排列。点击 HTML 的“下单时间”表头可切换升序和降序，只改变页面展示，不改变 JSON 审计顺序；缺少下单时间的行在两种方向下都排末尾，并用订单 ID、订单行 ID 稳定打破并列。Shopee HTML 隐藏“订单行 ID”列，但 JSON 必须继续保留该字段用于审计、去重和稳定排序。结算时间、下单时间、汇率更新时间统一显示为 `YYYY-MM-DD HH:MM:SS（UTC±HH:MM）`，原始带时区值仍保留在 JSON 和页面排序属性中。订单表只保留 Seller SKU，并紧接显示净结算 CNY、商品总成本 CNY、广告费 CNY、本土履约费 CNY、利润和利润率；商品名称放在最右。取消单独的币种列，在原位置显示中文“联盟营销佣金(AMS)”列，把 `order_ams_commission_fee` 的当地币和 CNY 金额各显示一次，并从后方动态费用列排除该代码。联盟营销订单占比按已结算父订单计算，不按展开商品行计算：父订单在本期所有行的 AMS CNY 合计大于0即为联盟订单；JSON保留联盟/非联盟/全部父订单数、精确占比、CNY费用合计与分币种当地金额，HTML显示百分比和分子/分母。表格继续展示发货方式、数量、实付、当地币结算、实时汇率及来源、单件成本、广告基数/比例/来源/当地币金额、额外成本，以及其他费用代码独立列。国家列只显示国家/地区代码，不显示内部店铺 ID；有效 HTTPS 主图地址必须渲染成图片而不是 HTML 文字。HTML 中汇率显示八位小数，所有价格和成本显示两位小数；宽表必须在订单行上方和下方提供同步横向滚动条，无需拉到最后一行即可访问右侧列。JSON 保留完整 Decimal 精度、广告比例来源和 FX 快照身份。
7. 对 JSON 连续执行两轮独立审计。结算对账保留精确本币差额；绝对值不超过 `1e-12` 仅视为 Decimal 分摊尾差，超过则阻断。缺成本、SKU、数量、汇率、结算或广告证据的行不得贡献数值利润；剩余行合计只是诊断性部分结果，不是完整周期利润。
8. 只有 `ready` 且人工明确确认的月报才能进入本地知识库；周报和 `needs_review` 报表禁止入库。

### TikTok 发货方式与订单行 ID

TikTok 新拉取的每个已结算订单都必须从 `/order/202309/orders` 保留官方 `fulfillment_type`，同时保留 `delivery_type`、`shipping_type`、`delivery_option_name`、`warehouse_id` 和证据来源。已知枚举可加中文标签，未知枚举必须原样展示，禁止根据费用、承运商、店铺名或仓库文字猜测；新拉取缺失该字段必须报告质量问题。TikTok 和 Shopee HTML 都隐藏订单行 ID，但 JSON 和页面排序元数据继续保留。

## 安全门槛

- 所有平台调用仅限外部读取，回执必须是 `external_writes_performed=[]`。
- 不保存 token、Cookie、Authorization、API Key 或原始 API 响应。
- 保留所有原始费用名称/代码；只有 `included_in_net_settlement=false` 的费用才允许在净结算之外再次扣除。
- 缺失金额必须成为质量问题，不能转换为 0；唯一例外是已明确批准的缺成本临时政策，使用 CNY 5 并显示假设警告。
- 已批准知识库工件不可覆盖；修订必须创建新版本。

## 持续迭代

每次真实运行后，把可复现的适配、状态、费用、分摊或对账问题转为脱敏合成 fixture：先补失败测试，再修代码和英文合同，校验 Skill，最后重跑聚焦及完整测试。不得把某个订单号或一次性响应固化为永久规则。
