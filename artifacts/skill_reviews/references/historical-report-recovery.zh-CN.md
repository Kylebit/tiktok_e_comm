# 历史利润报表找回

当操作员要求重新打开以前生成的独立利润页面时，使用本模式。

1. 首先找到原始 `profit-report/*/v1` JSON。HTML、截图、下单日期标签和当前估算都不能替代财务事实。
2. 本地 `/profit` 直接展示保留的 `ee185c5` 订单级旧布局，不要求先选择文件。内置两行必须明确标记为合成数据，只能证明布局，绝不能当成业务事实。仅在取得原始 JSON 时使用 `/profit-archive`；文件只保留在浏览器当前页面内，并交给原订单级明细渲染器，不会持久化、刷新或重算。当前捕获快照复核工作台保留在 `/profit-review`。
3. 报表期间必须遵循对应平台合同。明细页的每日标签和日期筛选基于 `order_created_at`，不能证明每日结算覆盖。
4. 原样保留历史成本、汇率、广告、费用、结算与来源链路。不得用当前商品目录成本覆盖历史冻结成本。
5. 对同一期间重新拉取时，必须生成新的不可变快照和报告 ID，并比较结算事实 ID、订单 ID、结算日期、来源校验和、拒绝行与质量问题。禁止覆盖旧报表。
6. 原 JSON 缺失时，页面应明确显示工件缺失并停止。重新调用平台接口属于另一项需要明确授权的操作。
7. 新计算必须把一个规范内部 SKU 解析为一个跨平台、跨国家共用的当前采购成本；平台结算和各国费用/履约规则仍保持隔离。
8. 隔离报表只允许内嵌 PNG/JPEG/WebP/GIF 主图。不得宣称旧的远程 HTTPS 商品图已经恢复，也不得允许它触发网络请求。
