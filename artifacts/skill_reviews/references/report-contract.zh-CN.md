# 利润报表合同（中文审阅镜像）

TikTok 下单月份月报按官方 `order_created_at` 筛选，但每个纳入订单仍必须有截至声明日期的 Finance 结算证据。默认使用自然月内 `GMV Payment for TikTok Ads` 的实际扣款；操作员明确指定月度估算比例时，逐订单按买家现金实付商品金额计算，报表标为估算广告，实际 Finance 广告只作参考且不参与利润。带 `related_order_id` 的非订单调整先回挂原订单再计算利润。

客户拒收只有在官方原因/状态或操作员确认事实存在时才能应用退货成本规则：本土退货可再售，商品损耗成本为 0；跨境退货销毁，保留全部商品成本。退款、运费、广告和履约支出仍按实际证据保留，负结算结构本身不能作为拒收证明。

> 英文 [`report-contract.md`](../../../domains/data_operations/skills/manage-profit-settlement/references/report-contract.md) 是唯一执行来源。

## 纳入范围

只纳入 `settlement_status=settled` 的记录，以结算/放款日期判断周期。订单创建、发货、送达或普通完成状态不能证明已结算。

## 公式

`profit_cny = net_settlement_cny - product_cost_cny - advertising_cny - external_costs_cny`

同一报告周期内，同一订单商品行若有多个结算事实，只有在平台、SKU、数量、币种一致且最多一个事实具有正数买家实付广告基数时才允许合并。净结算和费用事实相加，保留每个事实 ID 与时间，商品成本和估算广告只扣一次。身份、数量、币种冲突或多个正广告基数必须阻断；禁止只修改重复行 ID、却静默重复扣成本。

净结算可能已经包含佣金、交易费、平台物流、退款、税和调整。全部费用行都要展示；只有明确标记 `included_in_net_settlement=false` 的费用才能额外扣除。

## 订单行证据

- 平台、店铺、地区、订单和订单行身份；
- 平台 SKU、seller SKU、成本 SKU、商品/规格名称和主图；
- 数量、单件/包装/计费重量及来源；
- 官方下单/发生时间（如平台提供）、结算时间和状态；TikTok 下单时间与 Finance statement 结算时间必须分开，Shopee 下单时间与 escrow 放款时间必须分开；
- 卖家折扣后的商品成交额、买家现金实付商品金额、净结算和币种；Shopee 平台券会减少买家现金但不减少卖家商品成交额，两者必须分开；
- 每个费用代码、名称、金额及是否已含于净结算；
- 单件/总商品成本、版本、生效时间、来源和快照；
- 广告金额、模式、基数/来源、截至时间、快照和分摊版本；
- 运行时实时读取的 FX 汇率、提供方、提供方截至时间和快照；整次报表运行只使用一个不可变快照；
- 外部成本、利润、结算快照和质量问题。
- Shopee 发货方式及官方进口税费证据；本土单还要保留合并后的本土履约费分摊和每个父订单的政策参数。

## 状态

- `ready`：全部纳入行都有结算、正数数量、成本、FX 和必要广告证据。
- `needs_review`：任一必要证据缺失或非法，禁止审批。

缺成本、SKU 映射、数量、FX、结算或广告的行不得贡献数值利润。其余行的合计只是诊断性部分结果，不能称为完整利润；必须报告计算行数、拒绝行数，并在已知时指出阻断 seller SKU。

经操作人批准的临时成本政策属于非阻断警告：缺成本单件按 CNY 5；冲突成本取最高正数。报表必须保留选中值、全部候选值、受影响 SKU 和政策版本。

周报是 `realized_settlement_with_estimated_ads`，各平台默认比例在统一 `report-policy.json` 中配置为 0.22，可全局或分平台人工覆盖。广告基数必须是买家现金实付商品金额，不能使用净结算金额，也不能包含买家运费：TikTok 使用 `customer_payment - customer_shipping_fee`，Shopee 使用 `buyer_total_amount - buyer_paid_shipping_fee`。卖家折扣后商品成交额必须另行保留。TikTok/Shopee 月报默认使用真实广告；缺少订单级归因时，也按买家现金实付商品金额分摊。操作员明确覆盖月度比例时，报表改为 `realized_settlement_with_estimated_ads`，逐订单按现金实付商品金额计算，并把真实 Finance 广告标成只读参考、不得参与利润。Ozon 当前周报和月报默认按 0.22 估算，也允许人工明确覆盖。估算报表必须保留比例、现金实付商品基数、政策版本，以及比例来自统一策略配置、全局覆盖、平台覆盖还是月报覆盖。

Shopee 必须按官方进口税费判断发货方式：`vat_on_imported_goods` 或进口关税（泰国为 `th_import_duty`）非 0 即为跨境；只有两项字段都存在且严格为 0 才是本土。字段缺失必须阻断；只有一项非 0 时仍保守标为跨境，但产生 `incomplete_cross_border_tax_pair`，不能成为 ready。本土订单默认每个父订单只扣一项合并后的本土履约费 CNY 4；在商品行间稳定分摊，保存为 `local_fulfillment_cost_cny`，加入 `external_costs_cny`，并写入幂等指纹。

订单行初始按结算时间降序排列；同一结算时间按订单 ID、订单行 ID 升序稳定排列。HTML 的“下单时间”表头可切换升序和降序，缺失时间始终放在末尾，并按订单 ID、订单行 ID 稳定打破并列；交互排序不得修改 JSON 审计顺序。HTML 提供按下单日期起止范围的包含式筛选，并在每次筛选后按父订单 ID 去重显示命中订单数、商品单位行数和每天的父订单数量；多件商品展开行不能重复计单。筛选启用时，底部“筛选合计”只汇总可见行的净结算、成本、广告、履约、利润、买家金额、AMS、额外成本和所有动态费用；清除筛选恢复整期合计，筛选不得修改 JSON 或整期审计合计。HTML 是展示层：只显示 Seller SKU，其后依次为净结算 CNY、商品总成本 CNY、广告费 CNY、本土履约费 CNY、利润、利润率；商品名称放在最右。取消单独币种列，在原位置显示“联盟营销佣金(AMS)”，同时展示 `order_ams_commission_fee` 的当地币和 CNY 金额，并从动态费用列排除该代码，确保只出现一次。联盟营销订单占比定义为AMS CNY合计为正的已结算父订单数除以全部已计算父订单数，禁止把商品行当成多个订单；JSON保留分子、分母、非联盟订单数、精确占比和AMS金额合计。国家列只显示国家/地区代码，不显示内部店铺 ID；有效 HTTPS 主图地址必须渲染为图片；实时本币兑 CNY 汇率、提供方和提供方截至时间必须独立成列，其他平台费用组件独立成列；汇率显示八位小数，所有价格/成本固定显示两位小数；宽表在订单行上方和下方提供同步横向滚动条。JSON 是审计层，继续保留完整 Decimal 精度和 FX 快照身份。

报表总成交额是各订单行“买家现金实付商品金额 × 该行审计汇率”的 CNY 合计。整体及单个商品行利润率统一为利润除以用户实付总成交额，不得使用净结算或卖家折后成交额。按下单日期筛选后，必须用当前可见行同步重算用户实付总成交额、利润和利润率。外部成本只包含净结算之外的成本；本土履约费必须作为其组成项明确展示，若外部成本全部来自本土履约，则显示父订单数、每单参数及乘积。已经包含在净结算中的平台佣金、税费和交易费不得重复扣除。

结算对账必须保留精确本币差额。绝对值不超过 `1e-12` 视为 Decimal 分摊尾差；超过该值则产生 `settlement_reconciliation_mismatch`。

## 知识库

只保存人工明确批准的月报。按平台/年/月保存不可变 JSON 和本地索引。拒绝包含秘密字段或原始响应的工件；修订产生新报告和新审批，不能覆盖旧版。
