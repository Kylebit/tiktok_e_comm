# Git 工作树治理

## 唯一主线

- `master` 是唯一可执行的业务主线。
- `tiktok_e_comm` 是唯一常驻工作目录。
- 根目录不是业务仓库；不得在根目录初始化或使用 Git。

## 任务分支

1. 每项长期代码工作从最新 `master` 创建一个任务分支和临时工作树。
2. 任务完成后先完成测试与提交，再合并或通过评审进入 `master`。
3. 合并后立即移除该临时工作树；不得保留以任务名命名的长期目录副本。

## 归档与恢复

- 历史副本仅保留为 `archive/*` 分支，不能继续承接新工作。
- 每次大规模整理前建立一个带日期的 `recovery/*` 标签。
- 未提交改动必须先成为明确的本地检查点，或被拆分为可审查的任务提交；禁止在多个目录分别积压。

## 提交卫生

- 不提交运行日志、队列状态、临时脚本、导出文件、生成报告、凭据或数据库。
- 功能代码、测试、必要说明应同批提交，提交信息描述业务结果。
- 推送远端前检查工作树是否干净，并确认不包含密钥或真实店铺数据。
