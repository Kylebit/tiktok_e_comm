# Monthly profit task: UNKNOWN agent attempt

Current state: **read-only inspection is available; automatic continuation is blocked**. This concerns the monthly `coverage` step only and does not alter the financial producer or settlement cutoff rules.

The adapter now atomically persists `agent_attempt_started` and `profit-agent-attempt/v1` in the task ledger before calling `ControlledAgentBridge.execute_monthly`. The receipt binds task ID, exact release, scope SHA-256, random attempt ID, output directory and input-note count. Concurrent duplicate calls cannot launch another agent against the same running attempt. A normal return records `agent_result`, including any session ID parsed from the CLI's `thread.started` event. A timeout may return `UNKNOWN` with a session ID; a process crash before that return can leave only the receipt and attempt directory. The agent writes inside that directory, so `agent-result.json` there is a candidate artifact, not independent proof of session ownership or completion. A session ID from stdout likewise needs an independent session readback. The fixed producer is reached only after a prepared result and source validation.

`inspect_unknown_attempt(task, profile)` reads the task's persisted checkpoint and verifies the entire receipt against current task identity before reading only the exact attempt directory under `artifacts/<task_id>/monthly-<attempt_id>`. It reports a candidate result file hash and a reported session ID when available, marks both as unverified, and always sets `automatic_resume_allowed=false`. It neither calls the agent nor opens the producer, provider, or financial source files. Legacy attempts without a receipt, mismatched identity or path-escaped attempts return `BLOCKED` without echoing an untrusted path or session ID.

To turn this into a recoverable workflow, add a read-only Codex session resolver that proves the original session identity, terminal state, command scope, and output path. The resolver must handle the crash window in which `thread.started` never reached the parent. The durable receipt proves the parent reserved one attempt; it does not prove a child started or ended. Only after exact session ownership and producer-input source validation should a separately reviewed transition clear the `UNKNOWN` gate. It must never rerun data collection or expand the latest contiguous fully settled date merely because an output file exists. Unresolved, still-running, or conflicting session evidence remains `UNKNOWN`.
