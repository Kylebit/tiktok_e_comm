# Original prepared product continuation

The startup-owned original-task receiver admits retained R1 and completed R2
from their own source roles. It does not replace the original task release with
the running controller's HEAD. Five source roots/HEADs/manifests, six exact R2
files, original state, prepared reference and the retained quiescence event are
checked before domain consumption. Admission does not rerun R1, image generation,
translation or image QA and supplies no publishing approval.

The original leased executor alone may bind the frozen four-digit SKU and adopt
the actual `native_r1` and full `native_r2` stage receipts. The original task,
history, R1/R2 digests, 15-shop predecessor and failed close event remain. Current
catalogue aliases, both release reservation namespaces, local approved-state
claims and other active task scopes must pass the concrete SKU reader. That
reader is local evidence; the existing release transaction owns reservation and
the native COMMON account/history/budget gates still own external use.

One immutable target cancellation is consumed by a separately pinned concrete
startup reader. Graph rebuilding, service projection, current-round checks,
COMMON and marketplace dispatch guards reread that durable record. An embedded
record or caller `consumer_adopted` flag cannot admit it. Marketplace payload,
review matrix and product locks use only the retained 14 shops. The COMMON plan
continues to bind its exact original R1/R2 predecessor.

The cancellation schema has a separate explicit three-object adoption operation,
CAS over every existing schema object/table row, online backup and an inactive
original-owner check. A page read cannot install it. Existing data and objects
must remain unchanged.

`original-prepared-task-continuation/v1` is a separate startup scope with no
new-task or historical worker. The legacy readonly and explicit-new-task modes
keep their existing rules. The original mode refuses native bootstrap unless
the coordinator-sealed deployment explicitly authorizes native ephemeral state
creation. It requires the existing native root and its existing owner-only ACL;
it does not create a replacement root or change merchant credentials. The normal
helper itself creates fresh owner-only helper/client subdirectories and local
session capability/CSRF carriers; that security state needs the specified
authorization before installation. Unknown native retirement retains the owner
and blocks replacement.

Source/unit validation and a readonly retained receiver check do not constitute
native installation, real stage adoption or a COMMON GO receipt. Original
executor release remains held until the formal owned startup, actual account,
SKU/reservation and full retained-target preflight are verified.
