# Orbit 任务工作台使用说明

点击左侧 Orbit 标识回到任务首页。这里安排工作、查看进度和处理待办；侧栏保留商品目录、商品上架、供应链、利润、知识工具五个业务入口。

## 同时安排三件工作

点击「新建任务」，每件工作各建一条，不必等上一件完成。例如：

| 任务 | 创建时填写 | 后续在哪里处理 |
| --- | --- | --- |
| 一轮新品上架 | 名称、采集箱 ID（如 3956742887）、准确目标店铺 | 完整候选就绪后，待办打开商品上架页的最终审核 |
| 下架不再销售的商品 | 名称、四位内部 SKU（如 0001）、准确目标店铺 | 任务详情查看执行与回读结果；无需新建一个审核页面 |
| 统计上个月利润 | 名称、统计月份、店铺范围 | 缺资料时在任务里补充；完成后打开该任务的报告 |

上架和下架需要系统支持的准确店铺标识，不要用“全部店铺”或自行缩写代替；不清楚时让执行 agent 先核对当前店铺范围。利润任务留空店铺范围时，执行前会从当前项目的可信配置解析并固定范围；店铺身份、站点或配置缺失会明确报出，不会把漏掉的店铺当作已统计。

三条任务分别记录进度，可以交错推进。同一商品、同一店铺的冲突操作会等待，利润读取不需要跟着商品写操作一起停下。创建成功说明任务已保存，不代表已经上架、下架或算完利润；还需要对应执行者和业务配置可用。

## 只处理需要你判断的事项

「待我处理」只列真正需要你判断或补充的事项。上架先由执行者准备商品事实、文案、价格、图片和目标店铺；这些准备步骤以及 COMMON 技术同步不要求逐轮人工批准。完整候选冻结后，在商品上架页一次查看商品事实、实际图片、价格和每个目标店铺，完成唯一的 `FINAL_MARKETPLACE_PUBLISH` 审核。资料缺失或技术失败会单独显示原因，不会把不完整的准备结果当作待审核候选。

页面保存与冻结候选、目标和动作一致的有效最终审核回执后，已连接的执行者会继续执行和逐目标回读；同一回执范围内的技术重试或等待平台结果不再要求重复审核。候选内容、目标或外部写入动作发生实质变化时，需要重新冻结并审核。任务记录里写一句“通过”不能代替商品上架页的准确审核。

需要补充资料时，点击「补充资料」，填写待办所要求的说明，使用「提交资料并继续」。确有已提供文件时可说明文件位置；无需填写命令或摘要值，也不要填写密码、令牌。提交成功后资料保留在记录里，任务重新排队；如果资料仍不完整，会再次列出具体缺项。补资料不会自动批准上架。

「执行异常」与缺资料分开。先看具体原因，技术问题由执行 agent 修复；允许安全重试的失败可点击「恢复任务」重新排队。「等待平台结果」表示系统在读取已有操作的结果，不需要你再批准；「核对执行结果」表示原操作结果尚未确定，不能重复提交。

## 查看结果与持续开发

任务详情显示当前步骤、执行者、更新日期和执行记录。「查看结果」打开该任务绑定的业务页面或报告；下架结果入口返回商品目录，具体执行回执保留在任务记录中。商品目录仍按内部 SKU 合并展示，并可修改该 SKU 的成本。供应链继续使用现有页面。

利润报告按店铺列明实际统计范围和截至已完全结算的日期。不同店铺的截止日期可能不同，不要把合计理解为已经覆盖完整自然月。缺广告、成本、订单来源或仍需复核时，即使已有 HTML 报告，也不代表整件利润任务已经完成。

日常真实业务使用稳定工作台。开发预览会显示预览提示，用于核对布局、流程和合成测试；预览中的审核或商业写入入口受限制，预览成功不能当作真实上架、下架或利润完成。

任务会固定其运行版本，技术记录收在详情底部。开发新版本与日常操作分开；切换版本后，旧版本任务需要由执行者核对恢复方式，不会悄悄套用另一套规则继续。你无需保持每个业务页一直打开，但工作台服务和对应执行者必须继续运行。

## 当前支持边界

三种模板统一保存范围、排队、补资料、失败恢复和结果入口。实际操作仍复用现有 Skill 与业务接口，完成状态依赖相应的业务核验。某类执行器未接入、资料准备失败或平台连接有问题时，任务会排队或显示具体异常，不会自动视为成功。

已有独立任务负责的工作可以显示为「已有任务负责」，这不是该任务此刻仍在运行的证明，也不会因此重复启动一次。取消待执行任务不会撤销已经发生的外部操作；结果未知时先核对原操作。无需为了保持进度反复创建同一件任务。
