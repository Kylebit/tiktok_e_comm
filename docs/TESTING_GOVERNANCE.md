# Orbit 测试治理与正式发布门禁

## 目标

这份规则服务于实际交付页面。先在精确候选核验路由、服务身份、工作流模式与 UI 合同；验收页面须和交付页面一致。当前产品是任务首页加五个一级业务入口，依据[项目入口](../AGENTS.md)与[任务运行方式](OPERATIONS_TASK_RUNTIME.md)核验；下列路由不是对所有分支或服务已接通的声明：

- Orbit 首页：`/`
- 商品目录：`/catalog`，一个内部 SKU 一条目录记录和一个当前成本。
- 商品上架：`/product-workspace`，在原审核流程中展示事实、文字、图片及逐目标发布结果。
- 供应链：`/supply-chain/`。
- 利润：`/profit`，以用户确认的七月原利润报告页面与[当前利润 Skill](../domains/data_operations/skills/manage-profit-settlement/SKILL.md)为基准；新月份按任务指定的店铺、订单/结算口径和来源交付。
- 知识工具：`/knowledge`。

用户已要求删除独立内容前端；AI 图片工作室、多语言图片结果、标题和历史图片工具不再是待建设或恢复的页面目标。文字和图片能力沿商品上架 Skill 与原审核页验收；视频复刻仍是独立开发范围，不据此新增一级入口。

当前[原利润报告入口](../shared_platform/original_profit_reports.py)将 `/profit` 定向到 `/profit-original/artifacts/profit_reports_monthly/2026-07/index.html`；部署时核验真实文件、白名单与哈希。后续月份通过任务结果入口交付，不能用七月样例或旧周报/SKU页宣称新月份已完成。

兼容页（历史如 `/new-product`、`/sku-profit`、`/release`）和旧图片/利润独立页面仅用于受影响的历史兼容回归，不因旧测试或本文恢复成当前产品目标。它们是否保留可访问由当前工单与路由合同确认；退役入口不得重新进入一级导航。UI 工单应给出唯一正式审核 URL 及明确兼容关系，不凭旧 Skill 或旧路由清单宣称整合完成。

## 验证范围

- 纯文档：审差异、语义、链接/锚点和实际源码入口，不添加只匹配本文句子的测试，不重跑无关业务套件。
- 实质行为缺陷：以下先红后绿规则；优先现有有效测试或真实浏览器复现，缺覆盖时再增加有价值回归。实现回执运行真实受影响集合，身份、金额、授权、未知恢复等合同/安全行为的负向场景不得省略。
- 低影响、可逆的文案或样式调整：差异与适当视觉核验即可；涉及实际交互缺陷时按行为层级验证，不为流程要求制造镜像测试。
- 隔离组合：在 exact combined HEAD 运行明确的组合门禁，记录来源到重放提交及失败台账；局部通过不能写成整个候选/全仓通过。
- 最终发布候选：保留本页末尾完整 tests 与强制真实 Chromium 门禁。不得用聚焦回执替代，也不因一次全量环境失败无限重复整仓。
- 记录完整命令、运行时、cwd/HEAD、临时路径、结果/JUnit、未跑/skip/失败及重测原因。稳定相关失败修复；环境故障先用最小探针和可用环境有界复验，缺上游与缺外部授权分开登记。
- Windows 可选用已验证可用的 cmd/现有 Python 和本包唯一短 basetemp。2026-09-05 本机符号链接权限已有普通进程真实通过证据，不能沿用历史 skip 宣称无解；换主机/候选仍需核验。不要修改 skip 条件冒充通过。
- 运行分类域测试前先记录实际 `python --version` 和解释器绝对路径。该模块含 Python 3.10+ 的类型语法；本机 2026-09-22 用项目现有 `.venv` 的 Python 3.12.8 完成 66 项相关测试。其他终端的 `pytest` 若落到 Python 3.9 而在收集阶段报语法错误，应切到已核验的解释器原样复验，不能写成业务测试失败或通过。
- Windows 上重跑 `tests/test_round1_workspace_freeze.py` 的合成 HTTP/Chromium 链路时，显式设置 `ORBIT_HIVE_SETTINGS` 指向本仓库的 `config/settings.example.json`、`ORBIT_NODE_BIN` 指向已安装 Node、`NODE_PATH` 指向包含 Playwright 的现有 `node_modules`，并设置 `PYTHONUTF8=1`。使用独立短 `--basetemp`。缺配置、缺 Node/Playwright 或系统默认 GBK 解码产生的是测试环境失败；先补齐同一隔离环境再判断产品回归。该夹具的临时商品根不是 Git checkout，任务面板由夹具专用 web-only runtime 响应，不应要求给临时根造 Git 历史或放宽正式版本门禁。

## 证据口径

已有失败能绑定本次未修复源、输入和环境时直接复用，不为了再取得一次红色重复整仓。最终回执绑定实际运行/导入的源码路径与 hash，提交后内容未变不机械重跑；源码或依赖变化、出现新失败时才复验相关范围。唯一测试数、重复观察、子进程和实际调用的浏览器旅程分列。guard 拒绝事件也要如实列出：依赖导入时被拒绝并捕获的 IPv6 bind 不等于成功监听，更不能写成零事件；记录节点、调用栈和依赖 hash，不放松 guard 做绿。Q01/S03/R3/T00/S04 的详细失败留在各包原回执。

## Bug 修复的强制顺序：先失败、后修复

实质行为缺陷（包括 UI 不可点击、状态死路、接口异常和外部回读不一致）应有可重复失败证据。主开发、领域和独立验收任务按影响范围执行以下顺序；不要求每个低影响可逆改动新增业务测试：

1. 分析当前问题可能涉及的代码路径和权威状态来源。
2. 稳定复现问题并记录最小复现步骤、输入、环境和观察结果。
3. 优先选择已有有效测试或真实浏览器场景；缺少覆盖时才添加能证明问题、保护行为的最小回归。
4. 保存未修改基线的明确失败；可复用前述已绑定证据，缺少时才实际运行同一测试/场景。
5. 解释失败原因，指出根因所在的合同、状态机、持久化、交互或部署层。
6. 根因确认后才允许修改生产代码；不得按 Offer ID 或错误文案做特判。
7. 修复后重新运行同一回归和相关测试；影响页面时运行真实浏览器，影响服务时做本范围隔离服务验收。不得触发未经授权的真实平台动作。
8. 交付时输出修改前/后的结果对比，并确认外部写入预算与新回归结果。

若问题无法稳定复现，必须停止猜测性修改并明确列出缺少的日志、状态、请求、
数据或操作步骤。若修复工作在本规则确认前已开始，必须在独立的未修改基线
检出中补跑相同测试/场景并证明其先红后绿；不能只展示修复后的绿色结果。

## 为什么过去的低级 UX 问题可以通过

Python 单元测试、纯函数测试、HTTP handler 测试和静态源码断言各有边界。这些测试在合同、金额精度、审批门禁、幂等、无外部写入方面很有价值，但前端层存在以下盲区：

1. 静态测试看到 `hidden` 属性被移除，不代表 CSS 计算后的元素真的可见；父容器的 `display:none`、媒体查询、透明度和零尺寸都可能继续隐藏它。
2. 源码中存在按钮和事件监听器，不代表点击后用户能看到 loading、进度、成功或失败反馈。
3. HTML 中存在正式链接，不代表流程没有退回套壳页、兼容页或死路。
4. API 返回成功，不代表页面没有 JavaScript 异常、控制台错误、横向溢出或错误的成功文案。
5. 后端默认无写入，不代表页面首次打开没有意外触发 POST、付费生图、妙手写入或渠道发布。
6. 用最新 fixture 测通，不代表旧本地状态、缺字段状态或无数据状态可以安全迁移。

因此，静态断言只能作为快速合同测试，不能代替真实 Chromium 发布门禁。

## 测试金字塔与责任

### L0：纯函数与数据合同

- 金额使用 `Decimal`，币种、时间、来源和 calculation kind 明确。
- 去重、幂等键、审批指纹、状态迁移可重放。
- SQLite 使用临时 fixture；不得读取或修改生产库。
- 每个业务域只测试自己的合同，跨域事实通过 shared contract 传递。

### L1：HTTP 与工作流合同

- 正式 API 的成功、无数据、校验失败、冲突和内部失败都有明确状态。
- “无数据”和“失败”绝不能被包装为成功、ready、verified 或 calculated。
- 离线测试关闭真实外部写入、渠道发布和付费调用；生产执行使用[统一授权规则](THREAD_OPERATING_MODEL.md#authority)，不因技术开关再要求同范围业务批准。
- 测试断言真实第三方写入为零。最低传输边界的合成 provider 可记录模拟调用次数，必须明确区分 attempted/confirmed/unknown 和真实调用；不能把模拟计数当线上证据。

### L2：静态前端合同

- 正式路由直接承载业务，不依赖“前往详细工作台”式套壳跳转。
- 每个异步控件必须有四态：loading/progress、success、failure、idle。
- 反馈区域使用 `role=status`、`role=alert` 或 `aria-live`，不能只改按钮颜色。
- 商品事实字段的责任清晰：系统分配 Seller SKU；Kyle 可在锁定前编辑标题、采购成本、重量、包装尺寸和来源规格。
- 现有任务与业务区域支持并行浏览，切换或打开其他任务时保留当前审核输入，不互相覆盖。

### L3：真实 Chromium 发布 UX 合同

[test_release_ux_contract.py](../tests/test_release_ux_contract.py) 是当前浏览器回归入口；先核验其中实际场景和所用 JS 依赖。真实 Chromium 验收应覆盖：

- 计算样式、祖先可见性、尺寸和 viewport 交集，而不是只查 `hidden` 属性。
- 1440px 桌面和 390px 手机下无页面级横向溢出。
- 页面无未处理 JavaScript 异常和 console error。
- Kyle 的真实任务有一个可见、非空的下一动作。
- 异步提交期间能看到 loading/progress，完成后能看到 success 或 failure。
- 首次打开页面的 POST、付费调用、妙手写入和渠道发布次数为零。
- 旧状态/缺字段状态不会导致页面崩溃，也不会伪造完成。
- 利润报告缺数据、范围或结算覆盖不足、SKU 成本查询失败时不能显示 READY、CALCULATED 或成功样式；历史周报/SKU兼容场景适用同一失败语义，但不新增对应独立页面。

浏览器运行时缺失时，普通开发环境可明确 `skip`；正式发布环境必须设置
`ORBIT_REQUIRE_BROWSER_TESTS=1`，此时缺少 Node/Playwright/Chromium 会直接失败。

### L4：插件与人工验收

以下是离线自动测试不能独立证明的真实环境/视觉事实，不是每次新增人工审批：符合当前策略的自动 QA 与 agent 视觉检查可以提供证据，只有用户明确保留的最终业务决定或确实缺失的人类判断才请求用户。

离线自动测试本身不能证明以下事项：

- 妙手登录态、浏览器插件注入、跨域下载和回读。
- 真实 1688、TikTok、Shopee、Ozon 页面结构变化。
- 第三方验证码、风控、OAuth、限流和网络抖动。
- 图片商品一致性、文字水印、视觉质量和视频内容的人类判断。
- 最终真实发布与平台回读按[授权规则](THREAD_OPERATING_MODEL.md#authority)执行；人工视觉验收本身既不授予发布权，也不增加同一冻结范围的重复批准。

最终发布验收在所需 L0–L3 门禁通过后完成，使用实际交付页面。开发中可先做只读视觉诊断；它不能冒充最终验收通过。

## 异步控件目标合同

下表用于当前模式的产品整合验收；执行时对照生产 schema、路由与实际场景。同一冻结范围只批准一次不等于全平台只能有一个执行按钮；TikTok、Shopee、Ozon 独立执行与逐目标回读仍须保留。

| 页面 | 控件/动作 | loading/progress | success | failure |
|---|---|---|---|---|
| 商品发布中心 | 加入队列、刷新单品/全部 | 按钮 loading + 队列 activity | 队列消息 + 商品下一步 | 页面 alert + 商品卡失败 |
| 商品发布中心 | 保存商品事实 | 表单 submitting + revision 核对消息 | 新 revision + 售价/预检已刷新 | 冲突或失败消息，不覆盖旧 revision |
| 商品发布中心 | AI 平台标题候选 | 按钮 loading + 模型生成说明 | 英文母版、逐平台候选和审计签名 | 就地失败；不修改商品事实、不伪造候选 |
| 商品发布中心 | 已批准的平台执行动作 | 依据当前平台合同与服务端状态显示执行、只读刷新、对账或人工处理 | 持久任务状态与逐平台/目标账本 | 就地显示具体 blocker；同一冻结业务决定不增加相邻重复审批 |
| 商品发布中心 | 保存来源图片选择 | 按钮 loading | 更新后的本地选择 | 原位错误，不覆盖未保存选择 |
| 商品上架原审核页 | 查看 Skill 产出的文字、图片及语言资产 | 已有异步读取显示 loading | 当前资产及对应审核轮次、来源 | 原位读取失败；不将资产生成误报为审核或发布完成 |
| 商品目录 | SKU 记录读取、成本修改 | 查询或保存 loading | 单一 SKU 记录及当前成本保存结果 | 空状态、冲突或 alert；不覆盖历史成本事实 |
| 利润报告与任务结果入口 | 读取已生成报告、查看逐店覆盖 | 异步读取时显示 loading | 报告期间、订单/结算口径、来源时点、费用明细与真实完成状态 | 缺失/哈希冲突/读取失败明确显示；needs_review列具体缺口，不包装为已完成 |

七月原利润报告是保留的历史页面；不为套用本表给静态报告添加生成或重算按钮。当前利润 Skill 可以支持周报、月报和订单/SKU分析，这些后台能力不等于需要独立周报或SKU前端。供应链、知识工具和任务首页新增交互时同样遵循四态与真实浏览器门禁，按实际交付控件验收，不先创建空页面满足清单。

新增异步按钮时核验真实交互与上述状态语义；复用有效场景，缺覆盖时补充有价值的 Chromium 回归。只有合同本身变化才更新本文；不要把每个控件清单复制成三份强制维护项。

产品语义回归须绑定本次 workflow mode。当前有效批准由已有确定性入口持久化，页面不重复要求相同业务决定；具体授权条件只见[线程治理](THREAD_OPERATING_MODEL.md#authority)。技术执行页与人审页职责、各平台/目标的有效 next_action、禁用原因和旧状态迁移必须有真实 Chromium 旅程，不能只做字符串断言。

## 外部动作预算

离线自动化的预算固定为：

- 网络第三方请求：0（本地静态资源和被拦截的本地 API 除外）
- 生产/真实业务数据库读写：0；显式绑定当前工作包的临时合成 SQLite/报告 fixture 可写，记录根路径并防止默认值落回生产 data/reports
- 妙手写入：0
- 渠道发布：0
- 付费 AI 调用：0
- 通知推送：0

任何越过上述范围的真实第三方调用或生产读写令离线门禁失败。为持久化/HTTP 故障注入进行的本地合成 fixture 写入按测试范围计数，不与真实平台写混记。临时目录保留与提交规则见[线程治理](THREAD_OPERATING_MODEL.md#git)。

## 正式发布命令

最终发布候选完整 tests（开发回执按前述受影响范围选集合）：

```powershell
pytest tests -q -p no:cacheprovider
```

强制浏览器发布门禁：

```powershell
$env:ORBIT_REQUIRE_BROWSER_TESTS='1'
pytest tests/test_release_ux_contract.py -q -p no:cacheprovider
```

发布候选必须同时满足：

1. 全量 `tests/` 通过。
2. Chromium 发布 UX 合同通过且没有 skip。
3. 没有生产数据库、妙手、渠道或付费调用。
4. 指定验收者在同一实际交付页面完成最后视觉/流程验收；它不重新索取已有有效范围的业务批准，也不证明真实平台发布已完成。
