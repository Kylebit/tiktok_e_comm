# Orbit 测试治理与正式发布门禁

## 目标

这份规则服务于 Orbit 正式产品，而不是独立“测试台”。Kyle 验证的页面、自动化测试运行的页面和最终交付的页面必须是同一组正式路由：

- Orbit 首页：`/`
- 商品发布中心：`/product-workspace`
- AI 图片工作室：`/ai-image-studio`
- 利润中心（周报 + SKU 利润）：`/profit`

兼容页（例如 `/new-product`、`/sku-profit`、`/release`）可以保留，但不能冒充正式验收入口，也不能成为正式路由唯一能力的承载处。

## Bug 修复的强制顺序：先失败、后修复

任何 Bug（包括 UI 不可点击、状态死路、接口异常和外部回读不一致）都不得
在没有可重复失败证据时直接修改生产代码。主开发任务、领域任务和独立验收
任务统一执行以下顺序：

1. 分析当前问题可能涉及的代码路径和权威状态来源。
2. 稳定复现问题并记录最小复现步骤、输入、环境和观察结果。
3. 添加一条能够证明该问题存在的最小失败测试。
4. 在未修改的基线代码上实际运行该测试，保存明确的失败结果。
5. 解释失败原因，指出根因所在的合同、状态机、持久化、交互或部署层。
6. 根因确认后才允许修改生产代码；不得按 Offer ID 或错误文案做特判。
7. 修复后重新运行同一回归测试、相关测试、真实浏览器和必要的真实服务验收。
8. 交付时输出修改前/后的结果对比，并确认外部写入预算与新回归结果。

若问题无法稳定复现，必须停止猜测性修改并明确列出缺少的日志、状态、请求、
数据或操作步骤。若修复工作在本规则确认前已开始，必须在独立的未修改基线
检出中补跑新增测试并证明其先红后绿；不能只展示修复后的绿色结果。

## 为什么过去的低级 UX 问题可以通过

当前仓库的测试主体是 Python 单元测试、纯函数测试、HTTP handler 测试和静态源码断言。这些测试在合同、金额精度、审批门禁、幂等、无外部写入方面很有价值，但前端层存在以下盲区：

1. 静态测试看到 `hidden` 属性被移除，不代表 CSS 计算后的元素真的可见；父容器的 `display:none`、媒体查询、透明度和零尺寸都可能继续隐藏它。
2. 源码中存在按钮和事件监听器，不代表点击后用户能看到 loading、进度、成功或失败反馈。
3. HTML 中存在正式链接，不代表流程没有退回套壳页、兼容页或死路。
4. API 返回成功，不代表页面没有 JavaScript 异常、控制台错误、横向溢出或错误的成功文案。
5. 后端默认无写入，不代表页面首次打开没有意外触发 POST、付费生图、妙手写入或渠道发布。
6. 用最新 fixture 测通，不代表旧本地状态、缺字段状态或无数据状态可以安全迁移。

因此，静态断言只能作为快速合同测试，不能代替真实 Chromium 发布门禁。

## 测试金字塔与责任

### L0：纯函数与数据合同

- 金额使用 `Decimal`，币种、时间、来源和 calculation kind 明确。
- 去重、幂等键、审批指纹、状态迁移可重放。
- SQLite 使用临时 fixture；不得读取或修改生产库。
- 每个业务域只测试自己的合同，跨域事实通过 shared contract 传递。

### L1：HTTP 与工作流合同

- 正式 API 的成功、无数据、校验失败、冲突和内部失败都有明确状态。
- “无数据”和“失败”绝不能被包装为成功、ready、verified 或 calculated。
- 所有外部写入、渠道发布和付费调用默认关闭，并要求显式二次确认。
- 测试必须断言 `external_writes_performed == []`（或等价审计字段）。

### L2：静态前端合同

- 正式路由直接承载业务，不依赖“前往详细工作台”式套壳跳转。
- 每个异步控件必须有四态：loading/progress、success、failure、idle。
- 反馈区域使用 `role=status`、`role=alert` 或 `aria-live`，不能只改按钮颜色。
- 商品事实字段的责任清晰：系统分配 Seller SKU；Kyle 可在锁定前编辑标题、采购成本、重量、包装尺寸和来源规格。
- 商品发布中心与 AI 图片工作室使用新标签页并行打开，不互相覆盖。

### L3：真实 Chromium 发布 UX 合同

`tests/test_release_ux_contract.py` 会启动离线静态服务器，再用真实 Chromium 打开四个正式页面。它检查：

- 计算样式、祖先可见性、尺寸和 viewport 交集，而不是只查 `hidden` 属性。
- 1440px 桌面和 390px 手机下无页面级横向溢出。
- 页面无未处理 JavaScript 异常和 console error。
- Kyle 的真实任务有一个可见、非空的下一动作。
- 异步提交期间能看到 loading/progress，完成后能看到 success 或 failure。
- 首次打开页面的 POST、付费调用、妙手写入和渠道发布次数为零。
- 旧状态/缺字段状态不会导致页面崩溃，也不会伪造完成。
- 周报无数据、SKU 查询失败时不能显示 READY、CALCULATED 或成功样式。

浏览器运行时缺失时，普通开发环境可明确 `skip`；正式发布环境必须设置
`ORBIT_REQUIRE_BROWSER_TESTS=1`，此时缺少 Node/Playwright/Chromium 会直接失败。

### L4：插件与人工验收

自动化不能替代以下验证：

- 妙手登录态、浏览器插件注入、跨域下载和回读。
- 真实 1688、TikTok、Shopee、Ozon 页面结构变化。
- 第三方验证码、风控、OAuth、限流和网络抖动。
- 图片商品一致性、文字水印、视觉质量和视频内容的人类判断。
- 最终真实发布（属于高风险外部动作，必须由 Kyle 单独批准）。

人工验收只在 L0–L3 全绿后开始，并使用正式页面，不使用兼容页或测试台。

## 异步控件统一合同

| 页面 | 控件/动作 | loading/progress | success | failure |
|---|---|---|---|---|
| 商品发布中心 | 加入队列、刷新单品/全部 | 按钮 loading + 队列 activity | 队列消息 + 商品下一步 | 页面 alert + 商品卡失败 |
| 商品发布中心 | 保存商品事实 | 表单 submitting + revision 核对消息 | 新 revision + 售价/预检已刷新 | 冲突或失败消息，不覆盖旧 revision |
| 商品发布中心 | AI 平台标题候选 | 按钮 loading + 模型生成说明 | 英文母版、逐平台候选和审计签名 | 就地失败；不修改商品事实、不伪造候选 |
| 商品发布中心 | 审批、计划、妙手、发布 | 硬阻塞时禁用；中文标题/人工成本差异作为可确认提醒且按钮保持可用 | 本地审计/回读结果 | 可重试失败和运行账本 |
| AI 图片工作室 | 读取项目、保存审核 | 按钮 loading | toast + 更新后的本地状态 | alert |
| AI 图片工作室 | AI 分镜、预检、付费生成 | 专用步骤进度 | 完成/等待人工审核 | 失败步骤 + alert |
| AI 图片工作室 | 妙手同步 | 四步回读进度 | verified | 失败步骤 + 可重试原因 |
| 利润中心 | 周报 | 表单 loading + verdict loading | ready 或 needs-review | unavailable + alert |
| 利润中心 | SKU 查询 | 表单 loading | 样本、费用明细和估算状态 | 空状态 + alert；不得显示 CALCULATED |

新增异步按钮时，必须同时更新本表、静态控件清单和 Chromium 场景。

产品语义回归也属于发布门禁：同一个业务决定不能要求 Kyle 在相邻控件重复表达；自动完成的正常步骤不应继续显示为主按钮；禁用动作必须在同一区域说明具体 blocker；“通过”若已经代表纳入最终结果，就不能再要求一次“保留”。这类问题必须至少有一条真实 Chromium 旅程，而不只做字符串断言。

## 外部动作预算

离线自动化的预算固定为：

- 网络第三方请求：0（本地静态资源和被拦截的本地 API 除外）
- 数据库写入：0
- 妙手写入：0
- 渠道发布：0
- 付费 AI 调用：0
- 通知推送：0

任何非零调用都应令发布门禁失败，而不是仅记录 warning。

## 正式发布命令

开发快速回归：

```powershell
pytest tests -q -p no:cacheprovider
```

强制浏览器发布门禁：

```powershell
$env:ORBIT_REQUIRE_BROWSER_TESTS='1'
pytest tests/test_release_ux_contract.py -q -p no:cacheprovider
```

发布候选必须同时满足：

1. 全量 `tests/` 通过。
2. Chromium 发布 UX 合同通过且没有 skip。
3. 没有生产数据库、妙手、渠道或付费调用。
4. Kyle 在同一正式页面完成最后人工验收。
