# S01-A verified HTTP and bounded replay

Work order `WO-20260905-ORBIT-S01-A`, exact base
`fae95b44f607bd8965172a7acd5ba690d500a306`.
Only `core/http_retry.py` changes business behavior. Consumers are inventoried
read-only; no provider/client migration or service activation is included.

## Transport contract

- The shared default context requires certificate and hostname verification.
  Any explicitly supplied insecure context fails before a transport call.
  Secure custom contexts are passed through unchanged. Certificate verification
  errors, including wrapped errors, terminate immediately without retry/curl.
- Only bodyless GET/HEAD can retry. POST/PUT/PATCH/DELETE and every other method,
  or a GET with a body, send once and raise the original transport exception.
  An Idempotency-Key does not authorize replay. A POST used by a read provider
  is still single-attempt until the owning consumer establishes its contract.
- `attempts` is a positive integer and includes every transport attempt. Curl
  may use the final retry slot for an eligible read; it never adds an attempt.
  `attempts=1` never falls back. Timeout must be finite and positive; backoff
  must be nonempty with finite nonnegative delays, repeating the final delay
  if needed. HTTPError is propagated without replay, including 401/429.
- Curl uses certificate validation, disables curlrc, and has no internal retry.
  Its proxy is selected through urllib's environment/system proxy discovery and
  bypass decision, captured before a failed request can mutate proxy state.
  Explicit `--proxy` and an empty `--noproxy` preserve that decision; there is no
  `--noproxy *`, `-k`, or independent ALL_PROXY interpretation. Fractional
  network timeouts are retained; process cleanup receives a five-second margin.
- Every explicit SSLContext, including the shared default passed explicitly,
  remains on urllib. Custom CA environment settings and explicitly proxied
  Request objects also disable curl rather than silently changing routing or
  trust. This may reduce fallback availability; it does not reject secure
  contexts or disable their normal urllib read retries.
- Curl must produce an exact final three-digit status in 200–599. Missing,
  malformed, interim and out-of-range status output fails. HTTP errors preserve
  status/payload. Curl process errors do not expose stderr or command arguments
  containing authentication data.

## Evidence

The initial four regressions failed on the exact base: CERT_NONE default,
unknown POST outcome sent four times, and missing/malformed curl status each
fabricated success. The same four regressions then passed.

The final matrix has 76 passing tests, no skips. It includes real loopback TLS
using a self-signed certificate generated by the existing Git OpenSSL binary:
the default context rejects the handshake, with one urllib call and zero curl
calls; a caller context explicitly trusting only that fixture succeeds.
No trust certificate was installed into the machine or service configuration.
All other transport/curl responses are simulated; sockets/DNS are restricted
to that generated fixture and no real curl network process runs.

The directly related `test_shopee_client_transport.py` and
`test_toapis_client.py` also pass (19 tests), using their offline fixtures.
No existing test required weakening an assertion or consumer code changes.
