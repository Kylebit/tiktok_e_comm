# Task-bound delisting receipt

Package `TASK-DELIST-RECEIPT-01`, base `a8d9e9bc306b650a0663798fbd52e92682b358e2`.

Completed delisting tasks previously linked to the generic catalog. Saved readback
files were not referenced by their task, and execution rows could not distinguish
two products in one shop. This change exposes the existing evidence through
`GET /api/orbit/tasks/{task_id}/delisting-receipt`, including incomplete tasks.

The endpoint captures a bounded, checked rollback-mode database image and queries
it using SQLite `:memory:` / `deserialize` / `query_only`. SQLite never opens the
source database file. The capture rejects journals, WAL headers, oversized images,
links and changed file identity/content; it does not expire a lease, wake a worker
or call a provider. WAL, including a WAL-mode database with no sidecars, returns
HTTP 503 `RECEIPT_SNAPSHOT_UNAVAILABLE`. It neither ignores committed WAL pages nor
checkpoints, creates sidecars or changes journal mode. A dedicated stable snapshot
is required to support such a deployment. The ordinary WorkbenchStore defaults to
rollback mode. [SQLite's read-only WAL contract](https://www.sqlite.org/wal.html#readonly)
explains why `mode=ro` alone was insufficient.
Files must be referenced by that task's checkpoint/step, inside its private root,
regular local JSON, within the size limit, and match the saved raw-byte SHA256.
The plan's canonical digest, immutable scope and exact shop/product/SKU identities
are checked independently. Symlinks, junctions, dangling links, alternate streams,
conflicting refs and replaced files fail closed. No directory/latest-file lookup
or raw artifact download is provided.

Each product target shows execution evidence separately from the saved final
readback. An attempted UNKNOWN with count zero remains UNKNOWN. A full receipt
also requires completed task/domain records with the exact owner, resource set
and historical `delisting-result:` digest. Viewing never reconciles an operation
or releases locks. Missing legacy references remain an explicit evidence gap.

The adapter now persists a readback path/hash before validating the readback,
retains it on both success and failure, and saves the exact result URL on completion.
The existing Skill adds frozen product/SKU identity to execution rows. Provider
calls, authorization, domain claims and recovery behavior are unchanged.
The catalog/runtime manifests are regenerated by the existing source-maintenance
command because this additive Skill change changes its packaged content hash.
No personal Skill installation is updated.

Adjacent local and externally attached delisting task JSON is projected to public
metadata: private checkpoints, external evidence_ref, step receipts and event
payloads do not reach the browser. Worker/last-executor labels, a fixed truthful
pending-observation explanation, external owner and observation status/time,
input action IDs, version and per-task executor connectivity remain available.
External tasks retain their original result route and are not claimed as local
receipt owners. Malformed nested step checkpoints return a fixed error. The page has no
script, form or mutation control and sends no-store/nosniff and strict sandbox CSP.

Verification uses synthetic SQLite/files and a real engine/adapter/Skill/domain
chain with provider I/O replaced at the Shopee client/auth and identity-read seams.
It covers successful and ambiguous submission, repeated read-only GETs, cross-task
and hash/path/identity negatives, saved failed readbacks, legacy gaps and adjacent
API redaction. The zero-write regression compares exact file inventory and SHA256
before/after rollback and both WAL scenarios, and confirms SQLite only opens
`:memory:` (or no connection at all for rejected WAL). `tests/browser/delisting_receipt.cjs` exercises the real temporary
HTTP handler at desktop/mobile widths for complete, partial, missing and UNKNOWN
receipts; external origins and non-GET browser requests are rejected.
Exact executions and red/green JUnit are recorded outside the source tree in
`D:/OrbitEvidence/platform-next-gap-audit-20260923/delist-receipt-implementation`.

Limits: this is saved evidence, not a fresh provider query; it does not activate
a worker, repair old references, migrate business data or resolve UNKNOWN. The
local application remains single-operator, not a per-task multi-user ACL. Local
path/stat checks do not claim absolute protection against an attacker with OS
write privileges. Existing interrupted artifact writes remain visible gaps, not
automatically repaired files. Only this isolated candidate was changed.
