# /knowledge 条目介绍维护

`web/static/knowledge_guides.json` 是面向用户的说明数据，不是新的能力注册表或执行入口。
它按 `/api/orbit/navigation` 的稳定工具 ID 补充 13 个现有条目，不增加分类或一级导航。

每项包含一句摘要、使用场景、输入、产出、依赖与授权、限制、可复制中文示例，以及来源路径。
七个核心业务 Skill 另外在详情首屏显示三步执行顺序，便于看清先核对什么、何时写入、如何回读；该顺序只是介绍，不替代 Skill 原文、现场证据或授权。
示例默认先检查，使用者补齐占位内容后再交给 Agent；复制按钮不执行命令。
工程引用相对明确核验的代码根，H3 插件引用须从当前宿主定位，不固定个人缓存路径。

## 唯一来源与状态

- 分类、排序、标题、当前条件和技术命令仍来自 `shared_platform/orbit_registry.py` 对机器目录的投影。
- 介绍数据不得增加 stage/status/method/href/group 或账号可用字段；不把文案当业务授权。
- `reviewed_base` 仅表示介绍核对的源码版本，不表示账号、余额、运行环境或历史月份已恢复。
- 如果工程 Skill、已安装 Skill 或实际页面入口出现已核实的漂移，可以给对应介绍加带核查日期的 `source_notice`。它只提示差异和待核状态，不选择执行权威、不改机器目录状态；不要写本机绝对路径或把历史库存数写成实时数据。
- 所选工具目录未核验时，不显示新增调用示例；介绍读取失败时保留原目录和原技术方法并明确提示。
- 新 JSON/CSS 在 `shared_platform/runtime_identity.py` 的显式资产清单内；变化会使旧服务身份校验不符。

## 更新步骤

1. 阅读当前候选对应的 Skill 原文及相关脚本／API，而非仅根据名称改写。
2. 更新该 ID 的字段、可核实的 `workflow` 与 references；来源不存在时不能伪造脚本。宿主引用放 host_references。
3. 用普通中文明确只读、付费、需要批准和未接通的边界；不写密钥或真实账号。
4. 运行 `tests/test_knowledge_guides.py` 和 `tests/test_knowledge_guides_browser.py`。
5. 在桌面／窄屏检查展开、复制、筛选、条件失效和缺介绍回退；页面打开不得访问外部业务。

本轮范围：7 个流程 Skill（R1/R2/R3、下架、折扣、供应、利润），3 个独立工具
（TikHub、DuoPlus、Lingshi），2 个其他集成（H3、LinkFox）及1个知识快照入口。
目录原来的分类算法和顺序保留，不把完整机器目录的 vendor 参考文件重复加入页面。
