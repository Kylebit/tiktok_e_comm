# Agent与CLI来源规则

用户当前工作区根的 `ORBIT_STATUS.md` 是短状态锚；它记录当期角色、已验、阻塞和下一步。动态来源与证据以其时点为准，本页只保存稳定规则。

| 角色 | 含义 | 核验边界 |
|---|---|---|
| 用户工作区 | 对话上下文与固定状态位置 | 不因名字或盘符等同于完整Git根 |
| 完整开发候选 | 后继平台开发与隔离验证来源 | 源码/测试通过不代表已部署或业务完成 |
| 正式运行来源 | 当前批准部署及领域运行代码 | 核对入口、配置、数据、执行器与现场身份 |
| 历史工程/工作树 | 保留WIP、历史代码与业务资料 | 不自动认定clean、当前owner或执行授权 |
| 安全源码交付副本 | 可公开审查与GitHub交付的分支 | 不具有全部私有输入，不推其他分支或私有历史 |
| 个人Skill安装 | Agent发现的指令与脚本入口 | 核验物理resolve、脚本hash和实际导入根；安装匹配不等于独立CLI可用 |

当前角色可以同时指向不同来源；存在混用就明确标记未统一，不用一个Git根或一个PASS覆盖所有入口。

1. 先读工作区状态与本次工单，进入指定工程后核对Git top-level、branch、HEAD和dirty，再读其AGENTS.md。保留WIP，不从默认cwd推定canonical。
2. 每个Agent/CLI入口明确绑定完整source、config和data。优先使用入口现有的显式参数与可审计绑定；入口不支持或实际导入来源不符时保持阻塞，不依赖隐式fallback。
3. 个人脚本按自身文件路径解析的默认repo可能是安装目录。核验解析结果与导入发生时机；参数后置不能修复此前已经导入的错误来源。配置缓存、环境优先级和数据库相对路径也须按实际代码核验。
4. 将静态绑定、实际安全CLI、服务只读readback和真实业务端到端结果分别记录。存在可执行文件、HTTP成功或源码hash匹配均不能替代其他层的验收。
5. 正式服务、预览和独立商品runtime各按工单核身份。启动入口不用于查询状态；不为核验而启动、抢占或重放历史任务。
6. 数据、配置与执行器缺失时记录精确能力缺口，不创建空库或猜输入。供应链或其他领域保留的较新事实先审定继任来源，不以安装同步覆盖。
7. 本页与状态锚不新增商家写入、移动/删除或push权限；这些动作仍取本次明确授权与原有治理。
