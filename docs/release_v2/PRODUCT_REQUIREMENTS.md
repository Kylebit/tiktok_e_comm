# 自动上品发布 V2：软件需求规格说明书

状态：`DRAFT_FOR_KYLE_REVIEW`

产品负责人：Kyle

适用页面：`/new-product?offer_id={offer_id}`

适用阶段：商品、内容、价格、类目和目标均已进入已批准 `ReleasePlan` 之后

## 1. 产品目标

Kyle 在完成发布计划审批后，可以分别点击三个平台入口，把同一商品通过妙手提交到：

- TikTok：当前 `ReleasePlan` 选中的 TikTok 店铺；
- Shopee：一个 Shopee CNSC 全球商品，本版本不继续发布到各国家站点；
- Ozon：当前 `ReleasePlan` 中的 Ozon 目标。

操作必须直观、可重复、平台之间完全隔离。系统应如实说明妙手是否接受请求，不把“妙手已接受”冒充“店铺已成功上架”。

## 2. 核心原则

### PRD-001 每次点击都是新尝试 — `CONFIRMED`

每次点击“发布 TikTok”“发布 Shopee 全球商品”或“发布 Ozon”，都创建该平台的一次新发布尝试。

- 上一次成功不禁止再次提交；
- 上一次失败不禁止再次提交；
- 上一次结果未知不禁止再次提交；
- 旧草稿可以保留；
- 重复草稿在当前阶段可接受；
- 新尝试不得覆盖或伪造旧尝试的审计事实。

### PRD-002 历史不参与准入 — `CONFIRMED`

历史结果只用于展示和审计。任何 `FAILED`、`RECONCILIATION_REQUIRED`、`SUBMITTED_UNVERIFIED`、`SUCCEEDED` 或同义历史状态，均不得成为下一次显式发布的准入条件。

唯一允许临时阻止同平台再次点击的情况：该商品、该平台的一次尝试仍处于确定的执行中状态，目的是防止用户双击产生同一时刻的并发重复请求。执行结束、超时落为明确终态或服务重启完成恢复后，按钮必须重新可用。

### PRD-003 三个平台完全隔离 — `CONFIRMED`

- TikTok 的状态不能禁用 Shopee 或 Ozon。
- Shopee 的状态不能禁用 TikTok 或 Ozon。
- Ozon 的状态不能禁用 TikTok 或 Shopee。
- 一个 TikTok 站点失败，不得阻止同批次后续 TikTok 站点继续执行。
- 不存在 `TikTok -> Shopee`、`Shopee -> Ozon`、`COMMON -> 所有平台` 等隐式发布依赖。

### PRD-004 当前版本统一通过妙手 — `CONFIRMED`

当前版本的 TikTok、Shopee 和 Ozon 发布均通过妙手能力完成。平台官方 API 的直接发布、官方回读、自动对账暂时闲置，不参与本版本主流程。

### PRD-005 少量、明确的用户操作 — `CONFIRMED`

批准 `ReleasePlan` 后，页面只保留必要的平台操作：

1. 必要时重新导入妙手采集箱；
2. 发布 TikTok；
3. 发布 Shopee 全球商品；
4. 发布 Ozon。

同一平台内部不得再要求重复的“勾选确认 + 点击确认 + 再点击发布”，除非该确认代表不同的外部写入授权且已由 Kyle 单独批准。

## 3. 角色与术语

| 术语 | 定义 |
| --- | --- |
| `ReleasePlan` | Kyle 已批准、不可变的商品 revision、内容、目标、价格、类目和策略快照 |
| 采集箱导入批次 | 将公共采集箱商品分别准备为 TikTok 与 Shopee 妙手草稿的一次动作 |
| 发布尝试 `PublishAttempt` | Kyle 对某个平台的一次显式点击所创建的独立执行记录 |
| 目标尝试 `TargetAttempt` | 一个发布尝试中的单个 TikTok 店铺、Shopee 全球商品或 Ozon 目标 |
| 妙手接受 | 妙手 API 明确接受了提交请求；不等价于平台店铺最终上架成功 |
| 结果未知 | 请求可能已经到达妙手，但客户端未取得可判定回复 |
| 历史 | 已结束的采集箱批次、发布尝试及其目标结果 |

## 4. 范围

### 4.1 本版本包含

- 已批准计划的精确身份校验；
- 妙手采集箱重新导入；
- TikTok 多站点逐目标提交；
- Shopee CNSC 全球商品提交；
- Ozon 独立提交；
- 每个平台独立的新尝试；
- 每个目标的妙手接受、提交前失败或结果未知展示；
- 历史审计；
- 页面可操作性、错误提示和刷新恢复；
- 服务重启后的当前尝试恢复；
- 修改前红测与浏览器回归门禁。

### 4.2 本版本明确不包含 — `OUT_OF_SCOPE`

- 通过 Shopee 官方 API 直接发布；
- Shopee 全球商品继续自动发布到 PH/MY/TH/VN；
- TikTok、Shopee、Ozon 官方店铺回读；
- 因官方回读不一致而阻止下一次发布；
- 自动重试；
- 自动对账后重发；
- 跨平台依赖；
- 发布后自动促销；
- 雅仓库存事实对 TikTok 或 Shopee 发布的阻断；
- 离线优化指标改变生产发布规则；
- 根据历史结果自动选择是否重发。

## 5. 前置条件

### PRD-010 共同前置条件 — `CONFIRMED`

三个平台只共享以下事实，不共享运行状态：

- 当前商品存在；
- 当前 `ReleasePlan` 已由 Kyle 批准；
- 浏览器提交的 `offer_id`、`plan_id`、确认令牌和目标摘要与服务端已批准计划一致；
- 当前平台在计划中至少有一个目标；
- 当前平台没有正在执行的同平台尝试。

### PRD-011 TikTok 前置条件 — `CONFIRMED`

TikTok 发布必须获得本次计划对应的、每个选中 TikTok 目标的妙手草稿身份：

- 目标标签；
- 妙手 detail identity；
- 妙手 shop identity；
- 与 `ReleasePlan`、采集箱批次和目标绑定的摘要。

缺失草稿身份表示当前请求没有可提交对象。页面应明确提示“需要重新导入当前 TikTok 采集箱”，而不是“上次失败阻止发布”。重新导入完成后可立即创建新发布尝试。

GB 的业务决定：暂不做内容/价格/类目的差异校验，不因这些差异阻止 GB 提交；但仍必须有明确的 GB 草稿身份和目标店铺身份，禁止向未知对象盲写。

### PRD-012 Shopee 前置条件 — `CONFIRMED`

Shopee 当前只提交一个全球商品。它不得依赖 TikTok 采集箱结果、TikTok 发布结果或 Ozon 状态。

需要的商品事实来自已批准 `ReleasePlan`。是否复用采集箱导入产生的 Shopee 草稿由详细设计决定，但不得要求 TikTok 先成功。

### PRD-013 Ozon 前置条件 — `CONFIRMED`

Ozon 使用自身已批准目标和妙手目标身份。不得依赖 TikTok、Shopee 或雅仓当前库存决策。

如果 Ozon 必填业务字段缺失，应只影响 Ozon，并在 Ozon 操作区给出明确可执行提示。

## 6. 用户流程

### 6.1 页面加载

1. 页面读取已批准计划。
2. 页面分别读取 TikTok、Shopee、Ozon 的当前执行状态。
3. 页面读取最近历史，但历史显示在独立区域。
4. 三个平台按钮分别计算可用性，禁止使用一个全局 `posting` 状态同时禁用三个按钮。

### 6.2 重新导入采集箱

1. Kyle 点击“重新导入妙手采集箱”。
2. 系统创建新的导入批次；旧草稿和旧批次保留。
3. TikTok 为计划中所有选中站点创建或更新草稿，并保存逐目标身份。
4. Shopee 准备全球商品所需草稿信息。
5. 单目标失败不终止其他目标。
6. 页面逐目标显示结果；可以再次重新导入。

### 6.3 发布 TikTok

1. Kyle 点击“发布 TikTok”。
2. 服务端验证当前计划和最新草稿身份。
3. 服务端创建新的 TikTok `PublishAttempt` 并立即返回 `202 Accepted`。
4. 后台按计划目标顺序逐目标调用妙手提交。
5. 一个目标失败或结果未知后，继续下一个目标。
6. 页面轮询本次尝试并显示本次结果。
7. 本次结束后，按钮重新可用；再次点击创建下一次尝试。

### 6.4 发布 Shopee 全球商品

流程与 TikTok 独立，只创建一个 Shopee 全球商品目标尝试。本版本不自动发布到各国家站点。

### 6.5 发布 Ozon

流程与前两者独立，只处理 Ozon 目标。

## 7. 结果语义

### PRD-020 必须区分四个层级 — `CONFIRMED`

| 层级 | 页面用语 | 含义 |
| --- | --- | --- |
| 本地任务已创建 | “发布任务已创建” | 服务端持久任务存在，尚未表示妙手收到 |
| 妙手明确接受 | “妙手已接受提交” | 妙手接受请求，不表示店铺最终上架 |
| 提交前失败 | “未提交到妙手” | 有证据证明外部提交尚未发生 |
| 提交结果未知 | “提交结果未知，可再次发布” | 可能已提交；当前阶段仍允许用户新建下一次尝试 |

页面不得使用“发布成功”描述仅被妙手接受但尚未获得平台最终事实的目标。

### PRD-021 目标失败隔离 — `CONFIRMED`

- 目标失败不停止同平台其余目标；
- 目标失败不改变其他平台按钮；
- 批次结果为各目标事实的汇总，不用一个模糊全局错误覆盖明细。

## 8. 重试与重复提交

### PRD-030 显式新尝试，不是自动重试 — `CONFIRMED`

再次点击不是“恢复旧状态”，而是创建新的 `attempt_number`。旧尝试保持不可变。

系统不自动重试。是否再次提交由 Kyle 点击决定。

### PRD-031 并发双击保护 — `PROPOSED`

对同一 `offer_id + plan_id + platform`：

- 一个尝试处于 `QUEUED` 或 `RUNNING` 时，重复点击返回现有尝试，不创建第二个并发尝试；
- 该限制只持续到当前尝试进入终态；
- 不同平台允许并行；
- 页面按钮必须显示“该平台正在执行”，不能静默无反应。

### PRD-032 浏览器超时 — `PROPOSED`

浏览器在 POST 超时时，不得推断请求失败。它先按请求 ID 查询服务端：

- 找到尝试：继续展示；
- 未找到：明确显示“未创建任务，可以再次点击”；
- 查询也失败：显示“服务状态未知”，但不能用旧历史替代本次事实。

## 9. 页面需求

### PRD-040 主操作区 — `CONFIRMED`

批准计划后显示三个并列、独立按钮：

- 发布 TikTok；
- 发布 Shopee 全球商品；
- 发布 Ozon。

采集箱重新导入为独立辅助操作。不得恢复一个同时提交三个平台的“一键发布所有平台”按钮。

### PRD-041 禁用控件必须解释 — `CONFIRMED`

任何不可点击按钮或勾选框必须同时显示：

- 为什么不可用；
- 当前系统正在做什么；
- 用户下一步是什么；
- 是否会自动恢复。

禁止静默 `return`、无反馈点击、仅变灰而无说明。

### PRD-042 当前与历史分离 — `CONFIRMED`

主操作区只展示：

- 当前是否可发；
- 当前正在执行的尝试；
- 当前尝试结果。

“上次未发布”“上次结果未确认”“妙手已接受”等历史分组移到“发布历史”区域，默认折叠，不参与按钮可用性计算。

### PRD-043 刷新与服务重启 — `CONFIRMED`

刷新页面或重启本地服务后：

- 正在执行的尝试从服务端恢复；
- 已结束尝试进入历史；
- 按钮依据当前平台是否仍在执行重新计算；
- 不需要清浏览器缓存或重新批准计划。

## 10. 错误要求

每个错误必须包含稳定错误码、平台、影响范围和下一步。原始异常、凭据、响应正文和内部 ID 不得直接显示。

| 错误类型 | 是否创建尝试 | 是否影响其他平台 | 用户动作 |
| --- | --- | --- | --- |
| 计划身份过期 | 否 | 否 | 刷新并重新核对计划 |
| TikTok 草稿身份缺失 | 否 | 否 | 重新导入 TikTok 采集箱 |
| 同平台正在执行 | 返回现有尝试 | 否 | 等待当前尝试结束 |
| 妙手认证缺失 | 可记录提交前失败 | 否 | 恢复妙手配置后再次点击 |
| 妙手业务拒绝 | 记录目标失败 | 否 | 查看目标错误后再次点击 |
| 妙手响应超时 | 记录结果未知 | 否 | 可人工检查或再次点击 |
| 单个 TikTok 目标失败 | 记录目标失败 | 否 | 系统继续其他目标 |

## 11. 验收标准

### PRD-AC-001 历史不阻断

构造上一次 TikTok 六目标分别为成功、失败和结果未知的混合批次；点击发布后必须创建新 attempt，六目标重新进入本次尝试。

### PRD-AC-002 平台隔离

TikTok 正在执行、失败或结果未知时，Shopee 与 Ozon 按钮仍可点击并创建各自尝试。

### PRD-AC-003 目标继续执行

TikTok 第一个、中间或最后一个目标失败时，其余目标都按顺序执行一次。

### PRD-AC-004 防双击

同平台连续双击只产生一个当前尝试；按钮立即显示执行状态。另一个平台仍可启动。

### PRD-AC-005 历史展示

旧结果只出现在历史区。历史区内容变化不得改变任何平台按钮的 `disabled` 值。

### PRD-AC-006 真实文案

妙手仅接受提交时，页面必须显示“妙手已接受提交，不代表店铺最终上架成功”。

### PRD-AC-007 浏览器闭环

在真实 Chromium 的桌面与窄屏环境完成：批准计划加载、重新导入、分别点击三个平台、失败提示、再次点击、刷新恢复；控制台错误和页面异常均为零。

## 12. 待 Kyle 评审的设计细节

以下不改变核心需求，但在编码前需要最终确认：

1. 同平台正在执行时，重复点击是聚焦现有尝试，还是显示只读提示；本草案建议聚焦现有尝试。
2. TikTok 草稿身份缺失时，“发布 TikTok”是否自动先执行重新导入；本草案保留两步，避免一次点击产生两类外部写入。
3. 发布历史默认保留多少次；本草案建议本地全部保留，页面默认显示最近 10 次。
