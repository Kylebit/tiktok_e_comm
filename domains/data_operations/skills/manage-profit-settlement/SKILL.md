# Manage Profit Settlement

Keep TikTok, Shopee, and Ozon execution independent. Never use one platform's settlement, advertising, SKU mapping, cursor, or result to complete another platform. Share only versioned cost and FX snapshots.

## Workflow

### Stage 1: official settlement evidence

1. Accept an explicit platform, site, inclusive start date, and inclusive end date. Confirm the period is closed in the site's reporting timezone.
2. Read [references/report-contract.md](references/report-contract.md) and the matching platform section in [references/platform-sources.md](references/platform-sources.md).
3. Pull and save settlement evidence before doing any profit calculation. Run `scripts/pull_settlement_evidence.py --platform PLATFORM --site SITE --start YYYY-MM-DD --end YYYY-MM-DD --project-root ROOT --output OUTPUT`. Pull only official settled/released finance records; reject pending, processing, cancelled, delivered-but-unsettled, or unknown states. Add `--allow-credential-refresh` only after explicit operator approval. For TikTok, refresh a disposable token copy and leave every production credential file unchanged. For Shopee, bind refresh to the token file under the explicit project root, retain a rotated refresh token by updating that configured file, and record the credential write scope in the evidence receipt.
4. Review the saved `settlement-evidence/v1` JSON and HTML with the user. Verify period/timezone, source counts, financial component names, detail failures, snapshot checksum, redaction, and `external_writes_performed=[]`. If the user requested only this first stage, stop here.
5. Keep API results in memory or an explicitly named redacted snapshot. Never run a legacy wrapper that cleans directories or overwrites CSV/HTML during a report preview.

### Stage 2: order-level profit

6. Build a versioned cost snapshot keyed by canonical seller SKU and one immutable FX snapshot from a live read for the whole run. Stop if every live provider fails; never substitute configured/default rates. Retain the provider, provider as-of time, snapshot identity, and full-precision CNY-per-local rate. Apply temporary cost policy `temporary-cost-policy/default-5-conflict-high/v1`: use CNY 5 per unit when no positive cost exists and select the highest positive value when catalog costs conflict. Retain an assumption warning on every affected report/SKU; never present either selection as catalog fact.
7. Adapt only reviewed `settlement-evidence/v1` artifacts. Run `scripts/build_weekly_from_evidence.py --evidence-dir EVIDENCE --project-root ROOT --output OUTPUT --start YYYY-MM-DD --end YYYY-MM-DD`. For one independent site artifact, add `--platform PLATFORM --site SITE`; never combine different Shopee sites into one report. Use the bundled `report-policy.json` as the single editable location for all three weekly advertising fractions and the combined Shopee local-fulfillment fee. It defaults every platform to `0.22` and charges one combined CNY 4 local shipping-and-warehouse fee per Shopee parent order. Use `--policy-config PATH` for another versioned policy file, `--ad-rate RATE` or the three platform-specific ad-rate flags for one-run advertising overrides, and `--shopee-local-fulfillment-fee-cny` for a one-run local-fee override. The script records the policy checksum and resolved values, reads `shop.db` with SQLite `mode=ro`, requires a live FX source, and writes report artifacts only.
8. For weekly reports, default each platform's advertising fraction to `0.22` (22%) unless the user supplies an explicit global or platform override. For Shopee, apply it to `order_discounted_price`, the product sales amount after seller discount and before Shopee-funded vouchers; keep buyer cash-paid product amount (`buyer_total_amount - buyer_paid_shipping_fee`) as a separate display field. Never use the cash-paid amount as Shopee advertising GMV because platform-funded vouchers still compensate the seller. For other platforms, apply the rate to the contract-defined buyer-paid product basis excluding buyer shipping. Preserve the rate, input source (`default_22`, global override, or platform override), policy version, and basis as an estimate in every report; never label it as actual spend. Exclude an actual TikTok advertising adjustment from the weekly order-settlement basis before applying the estimate, and reconcile the exclusion separately so advertising is never deducted twice.
9. For TikTok/Shopee monthly reports, require actual advertising evidence. Prefer order attribution; otherwise allocate an auditable actual total by buyer-paid GMV. Never silently fall back to zero or the weekly rate.
10. Default Ozon weekly and monthly V1 estimated advertising to `0.22`, but accept an explicit operator override and label it `operator-adjustable-ad-rate/v1`; never label it actual spend. Derive the advertising basis from positive `OperationAgentDeliveredToCustomer` product-sale components. When the finance artifact contains only platform SKU and no quantity, `--allow-ozon-read-enrichment` may read `/v3/product/info/list` and `/v3/posting/fbs/get` to obtain seller SKU and fulfilled quantity. Retain only redacted mappings/counts, never raw responses or credentials.
11. Generate one independent JSON/HTML report per platform and site. For TikTok and Shopee, query official order details by the settled order ID, retain explicit `create_time` as `order_created_at`/`occurred_at`, and display it independently from settlement time; never substitute payment, shipment, completion, release, or settlement time for missing order time. Do not invent an Ozon order-created time when the official read exposes only processing or shipment timestamps. For Shopee, use official import-tax evidence: classify an order cross-border only when both VAT on imported goods and import duty are non-zero; if both fields are present but either is zero, classify it local. Treat either missing field as blocking. Charge one combined local shipping-and-warehouse fee once per parent order, allocate it deterministically across its item lines, retain the allocation and policy, and include the policy in the run fingerprint. Consolidate multiple same-period settlement facts for one order line only when product identity and quantity agree and no more than one fact carries a positive advertising basis; otherwise fail closed. Sum settlement and fee facts, charge product cost and estimated advertising once, and retain every source fact identity/time in JSON and HTML. Keep the initial order-line projection sorted by settlement timestamp descending, with order ID and order-line ID as deterministic tie-breakers. Make the HTML order-created header toggle ascending and descending display order without mutating JSON; keep missing order-created times last in either direction and use the same identity tie-breakers. Hide the Shopee order-line ID column in HTML while retaining it in JSON and as a deterministic sort/deduplication identity. Render visible settlement, order-created, and FX as-of times as `YYYY-MM-DD HH:MM:SS（UTC±HH:MM）`; retain the original timezone-aware values in JSON and the HTML sort metadata. Follow the legacy order-profit table pattern: show only Seller SKU; place net settlement CNY, total product cost CNY, advertising CNY, combined local-fulfillment CNY, profit, and margin immediately after it; place product name at the far right. Render fulfillment type, order/product/quantity, Shopee product sales and buyer cash-paid product amounts as separate columns, live FX rate/provider/as-of time, unit cost, advertising basis/rate/input-source/local amount, external cost, and every platform fee component as its own column. Replace the redundant currency column with a dedicated Chinese `联盟营销佣金(AMS)` column for `order_ams_commission_fee`, showing both local currency and CNY, and suppress that code from the later dynamic fee columns so it appears exactly once. Calculate Shopee affiliate-order share from settled parent orders, not item lines: a parent order is affiliate when its period report lines sum to a positive CNY `order_ams_commission_fee`; retain affiliate, non-affiliate and total parent counts, the exact share, CNY fee total and local-currency totals in JSON, and display the percentage with numerator/denominator in HTML. Display only the country/region code in the country column and render a valid HTTPS main-image URL as an image rather than escaped markup. Display the FX rate at eight decimal places so small ratios remain meaningful; show price and cost values at two decimal places while retaining full Decimal precision and FX snapshot identity in JSON. Give wide HTML tables synchronized horizontal scrollbars above and below the order rows so every column remains reachable without scrolling to the final row. Review totals, every quality issue and assumption warning, negative-profit lines, fee inclusion semantics, source counts, settlement reconciliation, cost conflicts, and rejected rows.
12. Perform two audit passes from each JSON artifact. Recompute totals from order lines and confirm only settled rows were included. Treat absolute reconciliation differences up to `1e-12` local currency as Decimal allocation noise while retaining the exact difference and tolerance; larger differences remain blocking. Iterate with a failing fixture/test when an issue is reproducible.
13. Approve only a ready monthly report after explicit human confirmation. Use `scripts/profit_report.py approve-monthly`; never approve a weekly or needs-review report.

## Safety gates

- Treat platform reads as external reads, never writes. Require `external_writes_performed=[]` from an injected live adapter receipt.
- Default to no credential refresh and save a blocked receipt when a read credential is missing or expired. After explicit operator approval, TikTok may refresh only a disposable copy for that read run; record `credential_refresh_performed=true` and never overwrite the configured or fallback token source.
- Do not persist previews, mutate production databases, silently refresh credentials, send notifications, retry payments, or modify platform orders.
- Preserve raw fee names and normalized codes. Subtract only costs not already included in net settlement.
- Represent missing money as a quality issue, never numeric zero. The only current exception is the explicit temporary missing-cost policy, which uses CNY 5 and must emit an assumption warning.
- Keep approved knowledge artifacts immutable. Create a new report version for corrections.
- Do not store tokens, cookies, authorization headers, API keys, or raw responses in reports or knowledge artifacts.

## Iteration rule

Treat this skill as a versioned operating procedure. After each real report, capture reproducible adapter, status, fee, allocation, or reconciliation failures as synthetic/redacted fixtures; add a failing test; update the domain engine and the relevant reference; validate the skill; then rerun focused and full tests. Never encode a one-off order ID or marketplace response as a permanent rule.
