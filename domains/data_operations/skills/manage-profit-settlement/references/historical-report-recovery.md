# Historical report recovery

Use this mode when an operator asks to reopen an earlier standalone profit page.

1. Locate the original `profit-report/*/v1` JSON first. HTML, screenshots, order-date chips, and a current estimate are not substitutes for financial facts.
2. Use local `/profit` for the current monthly task hub. Its July 2026 TikTok section links to the operator-selected, checksum-pinned read-only originals under `/profit-original/artifacts/profit_reports_monthly/2026-07/`; opening an original requires the configured asset root and a matching checksum allowlist entry. A historical report is not a current-month settlement or calculation result. The separate `/profit-partial-review` holds the frozen TH partial candidate with 428 item rows and 409 redacted parent orders; it is actual historical partial settlement evidence but is not an authoritative profit report. Keep the two-row synthetic `ee185c5` layout proof separate at `/profit-legacy-layout`, and never use its values as business facts. Use `/profit-archive` only when an original JSON profit artifact is available. That tool keeps the file in browser memory and passes it to the retained detailed renderer; it does not persist, refresh, or recalculate the report. Keep the newer captured-snapshot review workspace at `/profit-review`.
3. Treat the report period according to its platform contract. The full profit renderer's daily chips and date controls are based on `order_created_at`; they do not prove daily settlement coverage. A historical partial candidate without `order_created_at` must label its controls and daily counts as settlement-date filters based only on the retained site-local `settled_at`. Never copy settlement time into the order-created field.
4. Preserve historical cost, FX, advertising, fee, settlement, and source lineage exactly. Never replace a frozen historical cost with the current catalog cost.
5. For a refreshed period, create a new immutable snapshot and report ID. Compare settlement fact IDs, order IDs, settlement dates, source checksums, rejected rows, and quality issues. Never overwrite the earlier report.
6. If the original profit JSON is missing, show the missing-artifact gap. A separately reviewed historical settlement candidate may be displayed only in a checksum-pinned, fail-closed partial mode: retain known local settlement/sales/legacy fee values, show unavailable cost/FX/CNY/profit as `未具备`, and state incomplete pagination, shop binding, fee coverage, and month coverage prominently. A new marketplace pull is a separate explicitly authorized operation.
7. New calculations must resolve one canonical internal SKU to one current procurement cost shared by all platforms and countries. Keep platform settlements and country-specific fee/fulfillment rules isolated.
8. The isolated report view permits only embedded PNG/JPEG/WebP/GIF images. Do not claim that an old remote HTTPS product image was recovered or allow it to trigger a network request.
