# 妙手单品折扣页面契约

## 只读研究结论（2026-09-01）

妙手 TikTok 单品折扣页为：
`https://erp.91miaoshou.com/tiktok/marketing/discount`。

页面可管理 LivelyHive SEA、HomeBloom SEA、MX 和 GB 店铺的折扣活动。完整滚动
到列表底部后，当前可见列表中 LivelyHive PH/MY/TH/VN、HomeBloom PH/MY/TH/VN、
MX、GB 都有进行中活动。这个观察会变化，每次执行仍必须重新读取完整列表，
不能把本页记录的活动 ID 当成固定配置。

不能以首屏或中段可见行判定某店铺缺少活动。只有核对页面声明的活动总数、
遍历全部分页或滚动到明确列表终点之后，才允许给出 `BLOCKED_ACTIVITY`。若完整
遍历证据不足，结果必须是 `RECONCILIATION_REQUIRED`，而不是“活动不存在”。

页面静态资源确认“管理产品”使用妙手内部页面接口：

- `promotion/discount/addPromotionItems`
- `promotion/discount/editPromotionItems`
- `promotion/discount/retryAddPromotionItems`
- `promotion/discount/deleteFailPromotionItems`

这些是页面内部接口，不等于已承诺稳定性的妙手 Open API。不得复制浏览器
Cookie、令牌或直接重放私有请求。只有仓库内正式妙手 Open API 客户端明确
支持同一操作时才走 API；否则使用可审计的浏览器页面。

## 浏览器流程

1. 在活动列表按精确店铺筛选，并读取全部分页；没有筛选条件时，核对活动总数
   并滚动到列表底部，确认已覆盖最后一行。
2. 只接受一个状态为“进行中”、折扣类型为“折扣”的活动；零个或多个都停止。
3. 打开“管理产品”，按正式发布回读得到的商品 ID 或 Seller SKU 搜索。
4. 核对完整 Model SKU 集合，为每个 SKU 填入冻结折扣值。
5. 在最终提交前展示店铺、活动、商品、SKU 数量和折扣。若用户已经批准绑定上述
   完整集合的不可变批次，不再逐行重复确认；任何集合漂移都必须停止。
6. 提交一次；若页面结果未知，不得再次点击。
7. 回到同一活动重新搜索商品，核对所有 SKU 的折扣并持久化截图/摘要证据。

## 批量补齐约束

- 不得因为同一 Seller SKU 在其他国家已有折扣，就把该比例复制到当前国家；
  已观察到同一 SKU 在不同国家同时存在 5%、30%、35% 的合法差异。
- HomeBloom 商品身份只接受精确商品 ID，或由已批准候选与商品图片资产哈希形成的
  唯一映射。标题相似、同 SKU、同主图任一单项均不足以自动写入。
- “一键全选搜索结果产品”只可用于搜索结果集合与批准集合完全相等的情况；否则
  必须逐个精确商品 ID 搜索并选中。
- 每店提交后必须记录妙手进度框的总计、成功、失败，并重新加载同一活动核对每个
  商品行的折扣值。进度框 100% 不是替代回读的证据。

不得点击“创建活动”“复制”“自动延续活动”“终止”或“同步活动”来解决
缺少唯一活动的问题。
